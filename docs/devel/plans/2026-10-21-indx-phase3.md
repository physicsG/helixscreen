# INDX Phase 3 (Device Actions) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This project's CLAUDE.md overrides both skills' review and verification cadence: see "Verification cadence" below.

**Goal:** Give a Bondtech INDX printer its device actions on the screen: speed mode, cycle every tool, seat-fault recovery, heater and fan calibration with the save that follows, the heater-model update after a material edit, a read-only tool offsets display, and batch Load.

**Architecture:** Every INDX name and command stays in `indx_contract.{h,cpp}` (commands, gates) and `tool_offsets.cpp` (the offsets row); `AmsBackendIndx` exposes them through the existing `DeviceSection`/`DeviceAction` surface the AMS device-operations overlay already renders. Five small generic seams are added where no existing one fits, each vendor-free: a tracked `run_device_action()` (completion callback, long timeout), an edit follow-up question on `AmsBackend`, `RecoveryAction::confirm_message`, a read-only offsets model in `helix::tool_offsets`, and a `DeviceAction::info()` factory plus a `tool_offsets` section kind. Confirms and the calibration flow are guided device flows in a new INDX UI module, as CFS and Snapmaker do theirs.

**Tech Stack:** C++17-compatible (the ESP32 image builds C++17), LVGL 9.5 XML, Catch2, the INDX mock (`HELIX_MOCK_AMS=indx`).

**Rulings (Preston, 2026-10-21, on this plan's questions):** Q1 device-operations overlay, four sections. Q2 speed mode any time. Q3 seat/remove buttons in the fault modal AND "Seat a tool by hand" where tool changers keep their calibration entry (Task 12). Q4 both calibrations. Q5 ask "Save & Restart" / "Later" after each successful run. Q6 grey out with "Turn the nozzle heater off first". Q7 offer only for the mounted tool or an empty head, never while printing, never for a no-hotend tool, never when the preset did not change. Q8 the last tool stays mounted and hot. Q9 the cycle confirm as written. Q10 a read-only Tool Offsets section. Q11 the Tool Offsets entry keeps its title on every printer, and its description comes from the printer's calibration provider (Task 12). D1-D7 and O1-O5 stand.

**Spec:** `docs/devel/plans/2026-10-21-indx-backend-design.md` (sections 2, 6, 12 item 3, 13 D3 and D5). Leaf doc: `docs/devel/FILAMENT_BACKEND_INDX.md`. Upstream sources read for this plan: BondtechAB/INDX `ae64179` (`macros/indx-tc-macros.cfg`, `macros/indx-cal.cfg`, README section 5) and `indx_klipper` `host/heater.py` (`cmd_CALIBRATE`, `cmd_FAN_CALIBRATE`).

## Global Constraints

- Vendor names, macro names and variable names appear only in `indx_contract.{h,cpp}`, `ams_backend_indx.{h,cpp}`, the INDX row of `src/printer/tool_offsets.cpp`, the INDX arm of `src/printer/tool_offset_calibration.cpp#guided_flow` (beside the Snapmaker arm; it calls `indx::supports_seat_by_hand`, never a macro name), `src/ui/ui_indx_device_flows.cpp`, `ui_xml/components/indx_flow_status.xml`, and the mock. Generic code asks capability questions (`.claude/rules/vendor-abstraction.md`); `scripts/check_vendor_branches.py` must not grow.
- Nothing outside the upstream contract is sent. New commands, all upstream: `MODE_STEALTH`, `MODE_NORMAL`, `MODE_SPORT`, `TC_CYCLE_ALL`, `MANUAL_TOOL_REMOVE`, `MANUAL_TOOL_SEAT TOOL=<n>`, `SET_TOOL_FILAMENT TOOL=<n> DENSITY=<d> HEAT_CAPACITY=<hc>`, `INDX_CALIBRATE`, `INDX_FAN_CALIBRATE`, `SAVE_CONFIG` (through `helix::ui::SaveConfigWatch` only, never a bare send).
- A macro-backed action is listed only when its macro is in `printer.objects.list` (`Contract::has_*`). `INDX_CALIBRATE`/`INDX_FAN_CALIBRATE` are `[indx]` module commands with no `desc=`, so they cannot be probed (`/printer/gcode/help` lists only `desc=` commands): they are offered whenever the contract is recognized.
- Reads added: `save_variables.variables.t<n>_offset_x|y|z` and `global_z_offset` (mm floats). Absence is no news, never zero.
- US English UI strings, no em-dashes, no comment archaeology, `kCamelCase` constants, no exceptions or RTTI in shared code, `#include "hv/json.hpp"`, spdlog only, `lv_tr()`/`TR_NOOP` on every user string.
- Declarative UI: the flow status line is an XML component bound to subjects; no `lv_label_set_text`, no imperative visibility.
- Threading: every gcode completion lands on a background thread; reach `this` only through `lifetime_`/`token.defer` (`dispatch_payload()` already does). Main-thread only for modals and subjects.

## Review Focus

1. **A calibration that never answers cleanly.** Klipper shuts down mid-run (model divergence trips `max_model_error`), Moonraker times the rpc out after 30 min, or the user restarts Klipper. Expected: the status line leaves "Calibrating", says it failed or may still be running, and no save is offered. Pinned in Task 5 (`[indx][device]` timeout and error cases) and Task 9.
2. **A speed mode the screen does not know.** A user macro set writes `mode: "ludicrous"`, or the frame has not arrived. Expected: the dropdown selects nothing it cannot prove, sends nothing on its own, and still offers the three upstream modes. Pinned in Task 5.
3. **A batch that includes a tool it cannot load.** A no-hotend tool, or a docked tool under a paused print. Expected: the whole batch is refused naming the tool and reason, nothing sent. Pinned in Task 7.
4. **The seat-fault confirm.** Tapping a recovery that carries `confirm_message` must not send until confirmed, and Cancel or a backdrop tap sends nothing and leaves the fault handled (no re-present loop). Pinned in Task 4.
5. **A material edit on a docked tool while another is mounted.** Upstream's `SET_TOOL_FILAMENT` applies `INDX_SET_MODEL_PARAMS` to the live model immediately, i.e. to the MOUNTED tool's heater model. Expected per ruling Q7: no offer in that state, none while printing, none for a no-hotend tool, none when the material maps to the same preset as before. Pinned in Task 8.
