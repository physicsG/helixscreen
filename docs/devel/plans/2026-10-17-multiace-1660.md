# multiACE on the Snapmaker U1: implementation plan (#1660)

Status: phases 0-3 are on main; phase 4 (device actions, `ACE_PRELOAD` batch loads) is open. What shipped is described in `docs/devel/FILAMENT_BACKEND_MULTIACE.md`. Source read: decay71/multiACE v1.27b (commit a1a7b91, `multiace/VERSION`
= 1.27b), `klipper/extras/ace.py` (23.2k lines), `filament_feed_ace.py`, `docs/ENGINE_API.md`.
Reference only: physicsG/helixscreen `develop/snapmaker-multiace` (its header and plan; it ran
on a head-mode rig, so its hardware findings are cited below as "physicsG saw", unverified here).

Ruling: `AmsBackendMultiAce : AmsBackendSnapmaker`. U1 heads, `T<n>` and `channel_state` stay
authoritative; ACE units are inventory upstream of a head. No integration through multiACE's
FastAPI web service. Engine contract is `ENGINE_API.md` (gcode verbs + the `ace` object).

## 1. Detection

- Discovery is unchanged: `printer_discovery_parse.cpp#parse_objects` already yields `ace` +
  `filament_detect` to `AmsType::SNAPMAKER` (#1426). **No new AmsType** (it would touch every
  switch over the enum; this is still a Snapmaker printer with all its pre-print, prefs and
  resume behaviour).
- Variant choice moves to the factory: `AmsBackend::create(type, api, client, hw)` gains a
  `const helix::PrinterDiscovery* hw = nullptr` parameter; `AmsState` passes `&hardware`. In the
  SNAPMAKER case: `multiace::present(*hw)` -> `AmsBackendMultiAce`, else `AmsBackendSnapmaker`.
- `multiace::present(hw)` = `filament_detect` present AND `hw.ace_object_names()` contains the
  exact name `ace`. One module owns the predicate (vendor-abstraction rule).
- Subscription: `AmsBackendSnapmaker::required_status_objects` adds `ace` when
  `multiace::present(hw)` (one delegating line). `ace` is a plain object name, no space.
- Runtime gates, read from status (not discovery): `api_version != 1` -> log once, behave as the
  base backend (no ACE units); `mode == "normal"` -> same (multiACE swaps stock files back in and
  skips ACE detection, `ace.py` ~L3389). `multi`/`head` -> full behaviour. Mode can flip at
  runtime (`ACE_RUN_MODE_SWITCH`, multi<->head with no reboot), so the unit list is rebuilt on
  every `mode`/`head_ace`/`head_feeder`/`head_manual`/`aces` change.

## 2. Data model: head -> ACE unit -> slots

Global slot indices (addressing key, never relabelled):

| Global index | Meaning | Unit |
|---|---|---|
| 0..3 | U1 head h (inherited verbatim, every base per-head array stays valid) | unit 0 "Toolheads", PARALLEL |
| 4 + 4k + s | ACE unit k, bay s (k = `aces[k].idx`, s = 0..3) | unit k+1 "ACE k+1" |

`constexpr int multiace::bay_global(int ace, int slot)` and `std::optional<std::pair<int,int>>
multiace::bay_of(int global)` are the only translation. Base code bounds-checks `< kNumTools`
everywhere, so indices >= 4 never reach inherited per-head logic; the subclass owns them.

Per head, `HeadFeed head_feed(Mode, manual, feeder)` mirrors `ace.py#head_uses_ace`:
manual -> MANUAL; head mode and feeder -> FEEDER; else ACE. Per mode, the bays that can feed
head h (`candidate_bays`, mirrors `head_ace_for` + `cmd_ACE_LOAD_HEAD`'s 1:1 refusal):

| Mode | ACE unit topology | Bays that can feed head h | Unit -> head |
|---|---|---|---|
| head | HUB, 4 bays merge | the 4 bays of ACE `head_ace[h]` (only if head h is ACE-fed) | `hub_tool_label` = the h wired to it, -1 if none |
| multi | PARALLEL | bay h of every connected unit (1-to-N splitter per head) | bay s -> head s on every unit |

The **routed bay** of head h is `head_source[h]` (`ace_index`, `slot`), null = unloaded.
Head lane h's identity stays the base's (multiACE pushes `SET_PRINT_FILAMENT_CONFIG` on load,
`ace.py` ~L19914, so `print_task_config` already carries the routed spool). Every ACE bay's
`SlotInfo::extruder_name` = the extruder of the head it feeds (`extruder`, `extruder1..3`); in
multi mode bay s carries head s's name.

## 3. Status parsing (exact fields, `ace` object)

Pure parser `multiace::parse_ace_status(const json&) -> StatusDelta`, shaped like
`snapmaker_status_parse.h`: every field `std::optional`, absent key = unchanged (Moonraker
delta frames omit unchanged top-level keys; `aces` arrives whole when any nested value moves).
String dict keys `"0".."3"` throughout; a non-string key or wrong type = field dropped.

| Field | Type | Used for |
|---|---|---|
| `api_version` | int | gate (1 only) |
| `mode` | `normal`/`multi`/`head` | topology, gate |
| `head_ace{}` | int per head | head-mode wiring |
| `head_feeder{}`, `head_manual{}` | bool per head | `head_feed` |
| `head_source{}` | object or null: `ace_index`, `slot`, `type`, `color` (hex, "" = unknown, "000000" = declared black), `brand`, `subtype`, `load_failed` | routed bay, path segment |
| `ace_heads[]` | ints | cross-check only (log on disagreement with `head_feed`) |
| `swap_in_progress`, `swap_phase` (`idle|unload|load|flush|done`), `last_swap_result` `{head,ace,slot,status,ts}`, `event_seq` | | operation state, error surface |
| `unload_all_active` | bool | batch unload in flight |
| `aces[k]`: `idx`, `connected`, `connect_error`, `protocol`, `model`, `firmware`, `status`, `temp`, `humidity`, `dryer_status{status,target_temp,duration,remain_time}`, `gate_status[]`, `feed_assist` | | unit card, dryer, env, bay presence |
| `aces[k].slots[n]`: `index`, `status`, `sku`, `material`, `subtype`, `rfid`, `brand`, `color [r,g,b]`, `uid`, `tag_format`, `ident_src` | | bay identity + status |
| `spools{}` + `spool_binding{"<ace>_<slot>": id}` | separate deltas | bay identity layer 2 (physicsG saw `slots[]` empty for hand-entered spools; `spoolman_id` is a string, `color` bare hex, unbinding deletes the key so replace `spool_binding` wholesale) |
| `quad_replenish`, `quad_first` | bool | endless-spool capability (read-only) |

Ignored: `spoolman_url`, `tag_op`, `calibration*`, `nozzle_keys`, `settings_volatile`, PA and
tag-write settings. Bay status strings map through the shared `slot_status_from_string`
(`empty`/`runout` -> EMPTY, `ready`/`preload`/`running` -> AVAILABLE); `gate_status[s]` is the
presence fallback when status is unrecognised.

Head lanes keep the base parse of `filament_feed left|right` (shadowed by
`filament_feed_ace.py`, same shape): on an ACE head `filament_detected` is the **ACE gate**, a
bowden upstream of the head, so for ACE-fed heads the subclass does not treat it as port
presence at the head (`slot_has_prep_sensor` false, `slot_insert_presence` nullopt); the
toolhead switch and the `load_finish` latch stay authoritative.

## 4. Commands per operation

| Operation | ACE-fed head | Feeder / manual head |
|---|---|---|
| Load head lane h (0..3) | head mode `ACE_LOAD_HEAD HEAD=h`; multi mode names `head_source[h]`'s bay or refuses (a bare load takes the active unit) | `ACE_LOAD_HEAD HEAD=h` / `ACE_UNLOAD_HEAD HEAD=h` while the engine is active (review ruling) |
| Load bay (k,s) into its head h, h empty | `ACE_LOAD_HEAD HEAD=h ACE=k SLOT=s` (always pass both: SWAP defaults SLOT to head) | n/a |
| Load bay (k,s), h holds another bay, idle | `ACE_UNLOAD_HEAD HEAD=h` alone; `ACE_LOAD_HEAD` only after a frame shows `head_source[h]` null and the latch clear (review: a chained script loads nothing when the unload leaves the head occupied). `needs_unload_before_load` is false for a bay: the screen's swap ladder dispatches `ChangeTool(mapped_tool)`, a bare `T<h>` that loads no bay | n/a |
| Same while printing/paused | refused with the shared print-active refusal (`refuse_if_printing(paused_blocks=true)`), so no new user string | |
| Unload h, or a routed bay | `ACE_UNLOAD_HEAD HEAD=h`; terminal channel_state is `preload_finish`, not `unload_finish` (source: the ACE FEED_AUTO UNLOAD path in `filament_feed_ace.py` sets PRELOAD_FINISH) | inherited |
| Unload all | `ACE_UNLOAD_ALL_HEADS` when every selected head is ACE-fed; mixed selection -> sequential per head | inherited batch |
| Batch load | Phase 2: `not_supported` when any selected head is ACE-fed; Phase 4: `ACE_PRELOAD PLAN=h:k...` after the tester confirms grammar | inherited batch |
| Batch unload (as built) | `ACE_UNLOAD_ALL_HEADS` only when the selection is every loaded head (the engine unloads them all); any other selection is one line per head, `ACE_UNLOAD_HEAD` or `AUTO_FEEDING ... UNLOAD=1`, dispatched as one script without the base's per-head batch progress line | |
| Tool change / select | inherited `T<n>`; selecting a bay = `T<h>` only when it is h's routed bay, else "load it first" | inherited |
| Dry unit k | `ACE_DRY ACE=k TEMP=t DURATION=m`; stop `ACE_STOP_DRYING ACE=k` | |
| Endless spool | read-only: U1 stock auto-replenish stays base; `quad_replenish` exposed as a device-action toggle `ACE_SET_QUAD_REPLENISH ENABLE=0|1` (Phase 4) | |
| Rewire head (head mode) | device action `ACE_SET_HEAD_ACE HEAD=h ACE=k`, `ACE_SET_HEAD_FEEDER HEAD=h ENABLE=0|1` (Phase 4, idle only) | |
| Mode switch | never sent (ENGINE_API: the user switches mode in multiACE's UI) | |

Errors: multiACE raises coded errors (`id=525`, 200-band `code`, `ace.py#_ace_error`); extend
`classify_error` to file them as filament errors on head `index`. Push events: one
`notify_gcode_response` watcher (toolchanger zmod-watcher pattern, bg prefilter on the
`multiace_event ` prefix) parses `multiace_event <name> k=v ... seq=n`. `swap_failed` sets the
error segment on that head; `resistance_suspect` / `airlog_chew` raise a warning toast. The
status object stays the truth; events are latency hints, dropped when `seq <= event_seq` seen.

## 5. Topology and UI

- **Unit view.** Unit 0 draws as today (four PARALLEL heads). An ACE-fed head column gets an
  upstream caption "ACE 2 - 3" (from `upstream_slot`) drawn by the canvas, and its spool is the
  routed bay's colour (already true via `print_task_config`). A head-mode ACE unit draws HUB:
  4 bays -> hub -> its head's nozzle labelled `T<h>`; the routed bay is the active lane, the
  others idle. A multi-mode unit draws PARALLEL: bay s -> nozzle `T<s>`, a lane filled to
  NOZZLE only while `head_source[s]` names this unit. Unwired head-mode unit: hub, no nozzle.
- **System overview** ("units -> hub -> buffer -> toolhead"): four toolheads; each ACE head's
  chain comes from its ACE unit, each feeder head is a direct lane. The one generic change is in
  `ams_draw::compute_system_tool_layout`: a lane or HUB unit whose `extruder_name` names a
  nozzle already placed (including a PARALLEL lane's) shares that physical position instead of
  adding one. Without it a head-mode rig draws 8 nozzles and a 4-unit multi rig 20. The
  ACE-fed head's own unit-0 lane is then drawn as the chain's end, not a second spool
  (`upstream_slot(h)` present -> skip its spool box in the overview).
- **Numbering.** Spool badges count spools: an ACE-fed head and its routed bay share one
  number (physicsG hit 5-8 badges on a 7-spool rig). Generic: `spool_display_number(gi)`
  resolves through `upstream_slot`.
- **No source picker in this plan.** Choosing a bay and pressing Load is the switch. A picker
  on the head caption is a product call for Preston after the screenshots.
- Measure every new surface with `ctl geom` at 800x480 and 480x272 before Phase 3 lands.

## 6. Reuse

From `AmsBackendAce` (extract, do not fork): `parse_slot_color`, `read_slot_material`,
`slot_status_from_string` and the body of `apply_dryer_state_locked` move to a new
`include/ace_slot_parse.h` / `src/printer/ace_slot_parse.cpp` as free functions in
`helix::ace`; `AmsBackendAce` calls them (statics become one-line forwards or are deleted and
callers updated). `get_default_drying_presets()` and the ACE Pro dryer range constants are
shared, not copied. Not reused: `select_ace_object`, the REST bridge, `ACE_CHANGE_TOOL`,
endless-spool groups (multiACE has none of these).

From `AmsBackendSnapmaker` (inherit): everything for slots 0..3, `T<n>`, channel_state machine,
pre-print remap, prefs, resume, RFID on feeder heads, override store for slots 0..3.
New protected hooks in the base (each default = today's behaviour, U1 regression tests prove it):

```cpp
// ams_backend_snapmaker.h, protected; every hook runs with mutex_ held, so the
// override can read its own state without locking (the `_locked` suffix).
virtual bool head_is_upstream_fed_locked(int head) const { return false; }   // ACE head: gate != port
virtual bool preload_finish_ends_unload_locked(int head) const { return false; }
virtual void apply_extension_locked(const nlohmann::json& status, bool& changed) {}  // first in handle_status's locked block, one notify per frame
```

`head_is_upstream_fed_locked` gates `slot_has_prep_sensor` (now out of line, under the lock),
`slot_insert_presence` and the pending-insert arming in `apply_port_presence_locked`.
`preload_finish_ends_unload_locked` applies only when the channel's last in-progress state was
an `unload_*` (`unload_in_flight_`, beside `preload_in_flight_`): the frame then reads as
`unload_finish` for the op lifecycle, the unloaded-lane grace and the batch cursor.
